# [회신] 첨단 GPU 활용 지원 사업 – GPU 활용 현황 및 향후 활용계획 제출

수신: 첨단 GPU 활용 지원 사업 운영기관
발신: ○○○○ (기관명) / 담당자 ○○○
작성일: 2026-○○-○○

---

안녕하세요. 문의주신 GPU 활용 현황에 대해 아래와 같이 회신드립니다.

결론부터 말씀드리면, **활용 의지나 수요 부족으로 인한 저사용이 아니라, 3개 노드(master, n1, n3)를 단일 24-GPU 클러스터로 묶는 멀티노드 분산학습 구성이 완료되지 않아 대규모 작업을 투입하지 못한 것이 주된 원인**입니다. 이로 인해 현재는 노드당 8-GPU 범위의 단일 노드 작업만 수행 가능한 상태이며, 관련하여 **기술지원을 요청**드립니다.

## 1. 저사용 사유 및 현재 활용 현황

### 1-1. 자원 구성 현황

| 구분 | 노드 | GPU 수 | 역할 | 현재 상태 |
|---|---|---|---|---|
| 1 | master | 8 | 스케줄러 / 학습 겸용 | 단일 노드 학습만 수행 |
| 2 | n1 | 8 | 학습 | 단일 노드 학습만 수행 |
| 3 | n3 | 8 | 학습 | 단일 노드 학습만 수행 |
| **계** | **3노드** | **24** | — | **24-GPU 통합 클러스터 미구성** |

### 1-2. 계측 현황 (기간: 2026-○○-○○ ~ 2026-○○-○○)

| 지표 | 정의 | 측정값 |
|---|---|---|
| 자원 할당률(점유율) | GPU가 작업에 배정되어 있던 시간 비율 | ○○ % |
| GPU Utilization (SM Activity) | 커널이 1개 이상 실행 중인 시간 비율 | ○○ % |
| GPU 메모리 점유율 | 프레임버퍼 사용률 | ○○ % |
| 평균 전력 소비 | TDP 대비 | ○○ % |

> ※ 위 수치는 첨부 「진단 스크립트(gpu_cluster_diag.sh)」 실행 결과 및 DCGM/nvidia-smi 로그 기준으로 기재 예정입니다.

### 1-3. 저사용 사유 (중요도 순)

**① [핵심] 3노드 24-GPU 멀티노드 클러스터링 미완성 — 구조적 원인**

- 본 사업의 계획 워크로드는 24-GPU 단위 대규모 병렬 학습(대형 모델 사전학습·분산 강화학습)입니다.
- 그러나 현재 노드 간 집합통신(NCCL) 경로가 검증되지 않아, **3노드를 하나의 학습 잡으로 묶는 데 실패**하고 있습니다.
- 결과적으로 24-GPU를 요구하는 작업은 **투입 자체가 불가능**하며, 부득이 8-GPU 이하 소규모 실험만 수행 중입니다.
- 즉 **"쓸 작업이 없어서 논 것"이 아니라, "큰 작업을 넣을 수 없어서 논 것"** 이며, 상세 원인 분석은 첨부 「02. 24-GPU 클러스터링 기술검토」를 참조 부탁드립니다.

**② 모니터링 지표(GPU Utilization)의 계측 특성**

- `nvidia-smi`의 GPU Utilization은 **"직전 샘플 구간에 커널이 하나라도 돌았는가"** 만을 나타내는 이진(binary)에 가까운 지표로, 실제 연산 밀도(FLOPs 효율)나 자원 점유 여부를 나타내지 않습니다.
- 다음 구간은 GPU를 정상적으로 점유·사용 중임에도 Utilization이 0%로 계측됩니다.
  - 데이터 로딩 / 전처리 / 토크나이징 대기 (CPU·I/O 바운드 구간)
  - 체크포인트 저장 및 검증(evaluation) 사이의 동기화 구간
  - 분산 학습 시 all-reduce 통신 대기 구간 (특히 저속 인터커넥트 환경에서 비중 급증)
- 따라서 **할당률은 높으나 Utilization은 낮게 계측**되는 구간이 존재합니다.

**③ 사업 추진 단계상 데이터셋 구축 비중**

- 현 시점은 학습 데이터 정제·중복제거·토크나이징 등 **CPU 중심 전처리 단계**의 비중이 높아, 구조적으로 GPU 연산 밀도가 낮은 시기입니다.

**④ 공유 스토리지 및 데이터 스테이징 병목**

- 노드 간 공유 파일시스템이 없어 각 노드에 데이터셋을 개별 복제해야 하며, 이 과정에서 GPU 유휴 시간이 발생합니다.

## 2. 기술지원 등 필요사항

24-GPU 클러스터링 해소가 활용률 개선의 선결 조건이므로, 아래 항목에 대한 기술지원을 요청드립니다.

| No | 요청 항목 | 요청 사유 | 희망 시기 |
|---|---|---|---|
| 1 | **노드 간 인터커넥트 사양 확인 및 RDMA 활성화 지원** | InfiniBand/RoCE 가용 여부, 미가용 시 대안 확인 필요 | 즉시 |
| 2 | **NCCL 멀티노드 집합통신 검증 지원** | `nccl-tests` 24-GPU all_reduce 대역폭 기준값 제공 및 튜닝 | 9월 내 |
| 3 | **드라이버 / CUDA / NCCL 버전 정합성 표준안** | 3노드 간 버전 불일치 여부 점검 및 권장 조합 제시 | 9월 내 |
| 4 | **분산 스케줄러 구성 지원** | Slurm 또는 Kubernetes+Kueue 기반 gang scheduling 구성 | 9~10월 |
| 5 | **공유 스토리지 구성 가이드** | NFS/병렬 파일시스템 도입으로 데이터 스테이징 병목 해소 | 10월 |
| 6 | **모니터링 지표 산정 방식 협의** | GPU Utilization 단일 지표 외 **자원 할당률·메모리 점유율·전력** 병행 반영 요청 | 협의 요청 |

> **[요청 6에 대한 부연]** 대규모 분산학습은 통신 대기 구간이 필수적으로 발생하므로, GPU Utilization 단일 지표만으로는 실제 활용도를 과소평가할 소지가 있습니다. 사업 평가지표에 **자원 할당률(점유율)** 을 병행 반영해 주시면 실제 활용 현황이 보다 정확히 반영될 것으로 판단됩니다.

## 4. 종합 의견

- 본 기관은 GPU 자원 활용에 대한 명확한 수요와 계획을 보유하고 있으며, 현재의 낮은 Utilization은 **활용 의지 부족이 아닌 멀티노드 클러스터링 기술 장애에 기인**합니다.
- 해당 장애 해소 시 24-GPU 단위 대규모 학습 투입이 가능해져 가동률이 단기간에 큰 폭으로 개선될 것으로 예상합니다.
- 상기 **기술지원 요청 1~5번**에 대해 지원해 주시면 9월 내 정상화를 목표로 추진하겠습니다.

첨부 자료를 참고해 주시고, 추가로 필요한 로그나 자료가 있으면 언제든 요청해 주시기 바랍니다.
